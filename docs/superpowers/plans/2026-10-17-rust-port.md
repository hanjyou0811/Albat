# Albat Rust Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Execution method awaits user selection.

**Goal:** 言語仕様と生成C++の動作を保ち、変換器・CLI・WASMをRustへ完全移植する。

**Architecture:** 共有Rust変換ライブラリをCLIとWASMから呼ぶ。C++のライブラリ本文は生成コードの資産として保持し、旧C++変換器は比較専用に隔離する。構文とライブラリ全件の対応表を完了条件に使う。

**Tech Stack:** Rust/Cargo（edition 2021）、標準ライブラリ中心、WASMのみ任意依存のwasm-bindgen、CLIの一時領域にtempfile。互換性検証はPython 3、g++、ブラウザ自動化を使用する。依存導入時に公式情報で対応バージョンを確認し、Cargo.lockをコミットする。

**Spec:** `docs/superpowers/specs/2026-10-17-rust-port-design.md`

## Global Constraints

- 生成先は引き続きC++である。
- RustのCLIから既存C++変換器を起動する構成や、FFIで旧変換器を呼ぶ構成は完成とみなさない。
- 比較基準はクラッシュ修正済みコミット `6ab364e`。
- 既存6サンプルだけの成功を互換性の証明とはしない。
- 旧実装の未定義動作、クラッシュ、メモリリーク、変換間の状態漏れは再現しない。
- `int@a++` の既知の誤変換は移植と同時に暗黙修正しない。
- 変換器自身の通常ビルド・実行にはC++コンパイラを要求しない。
- 生成プログラムのコンパイルにはC++コンパイラが必要。
- サンプルの既存変更は保持し、テスト生成物は一時領域へ出す。
- WASMのビルドだけで動作確認済みとはしない。

## Review Focus

1. 文字列・コメント内の `@`、`**`、括弧、UTF-8を誤って構文と解釈しない（Task 2/5）。
2. 前の変換で要求したFastIOや型情報が次の変換へ漏れない（Task 3/8）。
3. ネスト・空ブロック・括弧不足で無限ループやpanicにならない（Task 4）。
4. 空白を含むパス、コンパイラ失敗、子プロセス失敗をCLIが正しく扱う（Task 7）。
5. 一時変数が利用者の変数と衝突せず、演算子の優先順位が変わらない（Task 5）。

## Files and interfaces

Cargoは標準の `src/lib.rs` / `src/main.rs` を使う。旧C++はTask 1で `compat/cpp/` に追跡対象を移し、参照ビルド専用とする。

| Path | Responsibility |
| --- | --- |
| `src/lib.rs`, `src/options.rs`, `src/diagnostic.rs` | 公開API、設定、位置付き診断 |
| `src/scan.rs` | 安全な文字列走査、トークン・括弧・引数境界 |
| `src/parser.rs`, `src/scope.rs`, `src/ir.rs` | 解析、型・変数情報、所有権のある出力構造 |
| `src/transform/{mod,io,operators,macros,declarations}.rs` | 言語変換 |
| `src/library/{mod,catalog}.rs`, `assets/cpp/` | 依存・排他解決、C++ライブラリ資産 |
| `src/emit.rs` | C++と#line生成 |
| `src/main.rs`, `src/cli.rs` | 引数、ファイル、コンパイル・実行 |
| `src/wasm.rs`, `albat.html` | WASMアダプタと既存画面への接続 |
| `tests/{scan,library,syntax,transforms,compatibility,cli}.rs` | Rust単体・結合テスト |
| `tests/fixtures/`, `tests/support/mod.rs` | 入力、期待出力、生成C++の検証補助 |
| `tools/compat.py`, `tools/test_web.mjs` | 旧版比較とブラウザ検証 |
| `docs/compatibility.md` | 機能→ケース対応表、意図した非互換・旧不具合 |

公開APIは以下を固定する。処理内部の型は利用するTaskで定義し、将来用の抽象化を増やさない。

```rust
pub fn transpile(
    source: &str,
    options: &Options,
    loader: &dyn SourceLoader,
) -> Result<String, Diagnostic>;

pub trait SourceLoader {
    fn load(&self, requested: &str, from: &str) -> Result<String, Diagnostic>;
}
```

`Options` は `source_name: String`、`main_signature: String`、`libraries: LibraryOptions`。既定値は `<stdin>`、`int main()`、旧 `libraryflg.h` の設定。`Diagnostic` は `source: String`、`line: usize`、`column: usize`、`message: String`（位置は1始まり）。`NoSources` はブラウザなどでファイル読み込みを明示的に拒否する実装。CLIは `FsSources` を渡す。

## Task 1: 比較基準と互換性ケースの固定

**Files:** `compat/cpp/`、`tools/compat.py`、`tests/fixtures/`、`docs/compatibility.md`、`makefile`。

**Interfaces:** `python3 tools/compat.py --reference <binary> --candidate <binary>`。各ケースはソース、入力、期待stdout、旧版の分類（正常/既知不具合/未対応）を持つ。プロセスにタイムアウトを設ける。

- [ ] 追跡対象C++とヘッダーを `compat/cpp/src/` へ移し、比較ビルド用Makefileを用意する。移動前後の旧CLI出力と6サンプルの結果が同じであることを確認する。
- [ ] 6サンプルの入力と期待出力を `run_sample.sh` から独立したfixtureへ記録する。`rep` の入力10は `1 3 6 10 15 21 28 36 45 55`。
- [ ] 全変換分岐とライブラリ登録を読み、設計書の棚卸し各行をケースIDへ対応付ける。発動できない旧機能は不具合欄へ分類する。
- [ ] 比較ハーネスを、意図的に誤ったstdoutを返す候補プログラムで実行し、非ゼロになることを確認する。
- [ ] 旧変換器同士の比較は成功し、生成C++のコンパイル失敗・実行失敗・タイムアウトはいずれも成功扱いされないことを検証する。
- [ ] `test: capture legacy behavior for Rust migration` としてコミットする。

## Task 2: Cargo基盤と安全な走査

**Files:** `Cargo.toml`、`Cargo.lock`、`.gitignore`、`src/{lib,scan,options,diagnostic}.rs`、`tests/scan.rs`。

**Interfaces:** `scan::split_top_level(source: &str, delimiter: char) -> Result<Vec<&str>, Diagnostic>`、`scan::matching_close(source: &str, open: usize) -> Result<usize, Diagnostic>`。位置はUTF-8バイト境界で返す。

- [ ] 次のテストを追加し、未実装による失敗を確認する。
  ```rust
  assert_eq!(split_top_level("f(1,2),\"あ,b\",v[0]", ',').unwrap(),
             vec!["f(1,2)", "\"あ,b\"", "v[0]"]);
  assert!(matching_close("(abc", 0).is_err());
  ```
- [ ] Rustパッケージと位置付きエラー型を実装する。文字列・文字リテラル・エスケープ・コメント・括弧を走査し、バイト境界外のアクセスを避ける。
- [ ] 空文字、コメント中の括弧、エスケープ引用符、UTF-8の前後での区切りを追加検証する。
- [ ] `cargo test --test scan` と `cargo fmt --check` が成功することを確認してコミットする。

## Task 3: ライブラリ全件の移植

**Files:** `src/library/{mod,catalog}.rs`、`assets/cpp/`、`tests/library.rs`、`docs/compatibility.md`。

**Interfaces:** `LibraryManager::new(&LibraryOptions)`、`request(&mut self, name: &str, already: bool)`、`set_enabled(&mut self, name: &str, enabled: bool)`、`is_enabled(&self, name: &str) -> bool`、`emit(&self, position: Position) -> Result<String, Diagnostic>`。`Position` はHead/Main。カタログは登録名・本文・位置・依存・親・削除規則・登録順序を持つ。

- [ ] 旧カタログ全件をfixture化し、名前・C++本文・登録情報の照合テストを先に追加する。件数を減らしたカタログが失敗することを確認する。
- [ ] 本文を文字列エスケープ解除して資産へ保存し、Rustへ埋め込む。通常ビルド時に旧版からの抽出処理を実行しない。
- [ ] FastIO/flush切り替え、依存の重複排除、親依存、既定pragma、標準名前空間、整数型設定のテストを実装する。
- [ ] 独立した2つのmanagerで要求集合が混ざらないことを確認する。登録を単なる辞書順で出力して旧順序を変えない。
- [ ] `cargo test --test library` を成功させ、全件照合結果を記録してコミットする。

## Task 4: 解析・スコープ・C++出力

**Files:** `src/{parser,scope,ir,emit,lib}.rs`、`tests/syntax.rs`、`tests/support/mod.rs`。

**Interfaces:** `parser::parse(source: &str, options: &Options, loader: &dyn SourceLoader, libraries: &mut LibraryManager) -> Result<Program, Diagnostic>`、`emit::emit(program: &Program, libraries: &LibraryManager) -> Result<String, Diagnostic>`。`Program` は順序付きの文/ブロックと各ソース位置を所有する。

- [ ] `transpile("int a = 1; cout << a;", ...)` の生成C++をコンパイルし、stdoutが `1` となる結合テストを追加して失敗を確認する。
- [ ] 旧parse/process/valid/type/get/skip/merge/varの分岐をRustへ移植する。関数、テンプレート、inline、クラス、namespace、ラムダ、単文ブロックをケースIDと紐付ける。
- [ ] includeはloaderを通じて解決し、読み込んだソースのファイル名を追跡する。循環読み込みは位置付きエラーとし、無限再帰を避ける。
- [ ] `#line` の行番号・ファイル名エスケープ、空ブロック、括弧不足、未閉鎖リテラル、空入力、明示mainと暗黙mainを検証する。
- [ ] 同一入力の連続変換でスコープが漏れないことを確認する。
- [ ] `cargo test --test syntax` を成功させ、対応表を更新してコミットする。

## Task 5: 独自構文・演算子・マクロ

**Files:** `src/transform/{mod,io,operators,macros,declarations}.rs`、`src/parser.rs`、`tests/transforms.rs`。

**Interfaces:** `transform::rewrite(statement: &str, scope: &mut Scope, libraries: &mut LibraryManager) -> Result<String, Diagnostic>`。`Scope` は識別子の登録・照会と `fresh_name(&mut self) -> String` を提供する。変換順序は旧 `library_check` / `setup_Line` / `setup_def` を基準に固定する。

- [ ] `int@a,b; $$(a+b);` に入力 `3 4` で `7\n`、`int a=1,b=2; (a,b)=(b,a); cout<<a<<b;` で `21` を期待するテストを追加して失敗を確認する。
- [ ] 入出力とオプション、宣言、型短縮、タプル、独自演算子・複合代入、スライス、ループ/順列、all/len/Count/境界検索を移植する。
- [ ] `2 ** 3` の結果8、演算子の混在、関数呼び出し・添字の左右辺を比較する。優先順位は数学的な推測で決めず旧版の有効ケースと照合する。
- [ ] `int@a++;` の既知挙動は入力5で4となる特性ケースとして区別して保持する。
- [ ] 同じ変数名を複数宣言したタプル、予約候補名に似た利用者変数、文字列中の `@ **`、UTF-8文字列が壊れないことを確認する。
- [ ] 全6サンプルをRustライブラリから変換し、コンパイル・実行・期待stdoutが成功することを確認する。
- [ ] `cargo test --test transforms` と対応表の未実装項目チェックを行い、コミットする。

## Task 6: ライブラリ利用と差分テストの完成

**Files:** `tests/compatibility.rs`、`tests/fixtures/`、`tools/compat.py`、`docs/compatibility.md`。

**Interfaces:** Task 1のケース形式をRustの `transpile` とTask 7のCLIでも利用する。出力比較は整形と生成一時名の限定的差分だけ許容する。

- [ ] 全ライブラリの挿入トリガー・組み合わせごとの最小利用例を追加する。未移植や欠落した依存で失敗することを確認する。
- [ ] 型・演算子・ネスト・プリプロセッサの未検証ケースを埋める。ACL等の外部依存が必要な場合は検証環境へ用意する。
- [ ] 正常な旧版ケースは生成C++と実行結果を照合する。登録名不一致・無効な指示等の旧不具合は一覧へ記録し、正常成功数へ数えない。
- [ ] `cargo test --test compatibility` を通し、未対応として黙って成功する分岐がないことをレビューする。
- [ ] 言語仕様の意味に影響する不一致が残る場合は原因を解消してからコミットする。

## Task 7: CLIと実行経路

**Files:** `src/{main,cli}.rs`、`tests/cli.rs`、`Cargo.toml`。

**Interfaces:** `cli::run(args: impl Iterator<Item = std::ffi::OsString>) -> i32`。`FsSources` がSourceLoaderを実装する。ネイティブ専用依存はターゲット条件でWASMから除外する。

- [ ] 標準入力変換、`run`、`--export` の有効ケース、`exec` のファイル入出力のテストを追加し、未実装失敗を確認する。
- [ ] 公開APIに接続し、`std::process::Command` と一時ディレクトリで生成C++のコンパイル・実行を行う。コンパイル設定は旧 `run` の `-O2 -std=gnu++20` を維持する。
- [ ] 入力 `int main(){return 7;}` のrun終了コード7、存在しないファイルの非ゼロ、コンパイル失敗の非ゼロを検証する。
- [ ] 空白・引用符を含むソースパス、相対include、標準入力のソース名、`--export` の生成シグネチャを検証する。コンパイラに到達できない場合も診断を返す。
- [ ] `exec` の修復と不正引数の扱いを互換性差分に明記する。
- [ ] `cargo test --test cli` およびTask 1の旧版対RustCLI比較を成功させてコミットする。

## Task 8: WASMとブラウザ

**Files:** `src/wasm.rs`、`Cargo.toml`、`albat.html`、`tools/test_web.mjs`、必要なら `package.json` / lockfile。

**Interfaces:** WASM公開関数 `process_string(input: &str) -> Result<String, JsValue>`。共有APIにOptions既定値とNoSourcesを渡す。生成JSは `bin/albat.js` に配置し、HTMLの読み込みをES moduleへ変更する。

- [ ] ブラウザでサンプル選択→変換→結果表示を行うテストを追加する。旧JSがない状態で意図どおり失敗することを確認する。
- [ ] 公式ドキュメントでWASMビルドとバインディングの使用方法を確認し、Rust共有ライブラリをラップする。JS側に言語変換処理を複製しない。
- [ ] Rustのwasm32成果物を生成し、ローカルHTTPサーバーから実ブラウザでテストする。
- [ ] 同じページでFastIOを使うソースと使わないソースを交互に変換し、ネイティブと同じ結果になることを確認する。不正入力の表示後も次の正常入力を処理できることを確認する。
- [ ] `node tools/test_web.mjs` の成功とブラウザコンソールエラーなしを確認してコミットする。
