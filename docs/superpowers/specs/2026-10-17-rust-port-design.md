# Albat Rust完全移植 設計

状態: 実装・独立レビュー指摘の修正・最終検証完了。結果は `docs/rust-port-validation.md`。

## 目的と完了条件

Albatの入力言語と生成C++の動作を保ちながら、変換器本体、CLI、ブラウザの変換処理をRustへ完全移植する。生成先は引き続きC++である。RustのCLIから既存C++変換器を起動する構成や、FFIで旧変換器を呼ぶ構成は完成とみなさない。

ユーザーは段階的な完全移植を選択した。仕様書が整備されていないため、クラッシュ修正済みのコミット `6ab364e` を比較基準とし、ソースから機能一覧と検証ケースを作る。既存6サンプルだけの成功を互換性の証明とはしない。

## 範囲

- 標準入力からAlbatを読み、C++を標準出力へ出すCLI。
- `run <source.al>` と `--export` の有効な使用方法。
- `exec <source> <input> <output>` のコマンド形状。ただし旧実装は欠落したシェルスクリプトを呼ぶため正常動作の比較対象にならない。Rustでは同じ変換・コンパイル経路を使って入出力をファイルへ接続し、失敗を非ゼロで返す。この差分は明示する。
- 既存のブロック、関数、テンプレート、型認識、スコープ、ラムダ、プリプロセッサ、ローカルファイルの取り込み。
- `@` 入力、`$` / `$$` 出力、入力オプション、型省略、タプル代入。
- 独自演算子と複合代入、ループ・順列マクロ、スライス、その他の置換マクロ。
- 組み込みライブラリ全件、依存関係、挿入順序、排他規則、既定設定。
- ソースファイル名と `#line` による行情報。
- `albat.html` からのWASM変換。変換を繰り返しても状態が混入しない構成。
- CargoとMake経由のビルド、テスト、利用手順。

出力C++のコンパイルには従来どおりC++コンパイラが必要である。変換器自身の通常ビルド・実行にはC++コンパイラを要求しない。

## 互換性の定義

正常に扱えるAlbatプログラムについて、構文の意味、生成プログラムの入出力、ライブラリの選択、外部インターフェースを維持する。整形や内部一時変数名の一致は必須としないが、比較時に無視できる差分は限定し、任意の識別子や式を正規化して誤変換を隠さない。

旧実装の未定義動作、クラッシュ、メモリリーク、変換間の状態漏れは再現しない。不正入力は位置付きのエラーを返し、CLIは非ゼロ終了する。未対応構文を黙って落として成功扱いにしない。

既知の `int@a++` が減算になる挙動は、移植の途中で暗黙に修正しない。現行挙動を特性テストで記録し、仕様修正を行う場合は独立した判断・変更として扱う。追加で見つかる、意味に関わる旧実装の不具合も互換性差分一覧に記録する。

## 構成

単一Cargoパッケージに共有ライブラリとネイティブCLIを置く。WASM固有の依存はオプションとし、通常のCLIビルドにブラウザ用ツールを要求しない。

共有ライブラリは、ソースと変換オプションを受けてC++または診断を返す。ファイル取り込みはホスト側の読み込みインターフェースを経由し、変換処理がプロセス全体の作業ディレクトリやグローバル状態に依存しないようにする。

1. ソース走査: コメント、文字列、エスケープ、括弧、トークン境界、行位置を扱う。UTF-8の途中を切らない。
2. 解析: ブロック、文、型情報、スコープを所有権の明確な構造へ格納する。C++の全構文を新たに実装するのではなく、既存Albatが解釈する境界を維持する。
3. 変換: 入出力、独自演算子、マクロ、宣言、タプル、スライスを処理する。
4. ライブラリ管理: 変換ごとの要求集合から依存・排他・順序を解決する。
5. 出力: C++と行情報を生成する。衝突しない一時変数名を変換単位で管理する。
6. CLI/WASM: 同じ変換APIへ接続する薄いアダプタ。

組み込みライブラリのC++本文はテキスト資産として保持し、Rustから埋め込む。これは生成プログラムの一部であり、旧変換器への依存ではない。登録情報と本文を分離し、移植時に全件・順序・依存を照合する。

`run` はシェル文字列を組み立てず、プロセスAPIでコンパイラと実行ファイルを呼ぶ。衝突しない一時ディレクトリを作成して終了時に片付け、終了ステータスを伝える。ブラウザはRust生成WASMの読み込み方法へ更新し、既存の入力・サンプル選択・結果表示を維持する。

## 段階と検証

1. 旧実装の全機能を棚卸しし、各機能とテストケースの対応表を作る。旧変換器を比較専用に隔離する。
2. 走査・解析・変換・出力を順に移植し、小さな構文テストと旧実装との差分を確認する。
3. ライブラリを全件移植し、登録情報の一致と利用例のコンパイルを確認する。外部ヘッダーが必要な機能は依存条件を明記し、必要な依存を用意して検証する。
4. CLIとWASMを同じ変換処理につなぐ。
5. 全互換性チェック後に標準ビルドをRustへ切り替え、旧C++変換器を本番構成から除去する。比較用コードを残す場合も開発用であることを明示する。

検証は次を含む。

- `cargo test`、`cargo fmt --check`、`cargo clippy`。
- 6サンプルすべての変換・生成C++のコンパイル・期待出力の照合。
- 構文ごとの正常系、ネスト、コメント・文字列内の記号、空入力、UTF-8、不正入力。
- 独自演算子の優先順位と複合代入、入力オプション、スコープと型認識、include/export。
- ファイル名・行番号、終了コード、標準入出力、空白を含むパス。
- 同一プロセスの連続変換でライブラリ選択が混入しないこと。
- WASMのビルドとブラウザ上の変換・連続実行。ビルドだけで動作確認済みとはしない。
- 新規環境向けのREADME手順とMakeターゲットの実行。

不足するツールや依存で検証不能な項目は明記し、未検証のまま完全移植達成と報告しない。比較テストはタイムアウト付きとし、旧実装の異常終了をRust側の期待結果にしない。

## 作業管理

専用ブランチ `refactor/rust-port` で作業する。元の作業ディレクトリにあるサンプルのバイナリ・生成C++はユーザーの既存変更として保持し、移植のコミットに混ぜない。テスト生成物は一時領域へ出す。

この設計書の承認後に、依存順序・具体的なファイル・各段階の検証を含む実装計画を作成する。その計画の確認と実行方法の選択を経て実装へ進む。

## 棚卸しで特に確認すべき互換性項目

以下は旧ソースから確認した検証対象であり、実動作の検証済み一覧ではない。

| 領域 | 実装上の対象 | 検証する振る舞い |
| --- | --- | --- |
| ループ | `rep/REP/rrep/RREP`、`fore`、`do_perm` | 引数数・増分・降順・参照変数・単文/ブロックの違い |
| 構造 | if/else-if/else、for/while/do、struct/class/namespace | ネスト、型登録、関数宣言と呼び出しの区別 |
| マクロ | all、len、Count、_upper_bound、_lower_bound | リテラル内を変更しないこと、入れ子引数 |
| コメント指示 | `//interactive`、`//atcoder` | 通常コメントとの境界、実際に有効なライブラリ選択 |
| 数値 | gcd/lcm、べき乗、切上げ除算、非負剰余、素数・約数、ビット演算 | 呼び出し名と登録名の対応、依存関係、入力の定義域 |
| データ構造 | UnionFind、WeightedUnionFind、SegTree各種、Fenwick_tree、MexSet | 必要なC++定義の挿入と利用プログラムの動作 |
| 剰余型 | mint/modint/mod_int と各初期化コード | 定数定義・初期化位置・依存順序 |
| IO | FastIO/FastIO_flush、istream/ostreamのpair/vector/set/map等 | 混在時の排他、interactive時の出力、選択順序 |
| ユーティリティ | chmax/chmin、biseek、runLengthEncoding、CycleLib、yesno、inversionnumber | 認識名と生成定義の一致、実行例 |
| コレクション | Slice、trim/ltrim/rtrim と文字列/vector版 | オーバーロード、依存選択、境界値 |
| 設定 | PRAGMA、STDCPP、NAMESPACE_STD、NAMESPACE_ACL、DEFINE_INT_LL | 既定値と変更可能な設定の対応、挿入位置 |

登録情報に存在しても、呼び出し検出と結び付かず旧版で使えない機能は「正常互換」のケースと区別する。例として `inversionNumber` の検出と `inversionnumber` の登録の表記差、`//atcoder` 内の無効化されたライブラリ要求がある。これらを移植時に無断で新たな言語仕様として有効化しない。

既存の `sample/io` などはテスト入力ではなく追跡対象の実行ファイルであり、サンプルテストが上書きする。Rust移植の検証では入力データと期待出力をテスト側で管理し、生成物をソースツリーに書き込まない。
