## 移植中の判断

- 機能一覧は旧実装の探索と差分実行を並行して埋めた。根拠のない仕様推測を避けるためで、見落としのリスクには最終レビューと追加回帰ケースで対応した。
- ライブラリ資産にはAlbatのループ記法が含まれるため、必要な変換を経て出力する。無変換で埋め込むと生成C++がコンパイルできない。
- 解析と独自構文の実装を同時に進めた。ライブラリやlambda内にも独自構文が存在するためで、コミット境界は一部統合した。
- デフォルト引数は定義に残し、前方宣言から除く。旧版で有効な定義後呼び出しを比較対象にした。定義前の省略呼び出しは新しい対応範囲にしていない。
- ライブラリ関数の前方宣言を生成する一方、クラスとその演算子の順序は保持した。誤ると依存関数や型が未定義になるため、trim系とクラス系の実行ケースで確認した。
- 元のライブラリ不具合は本文を変えずに保持し、旧生成器だけが壊す定義はRustで保持した。旧不具合の修正を期待する利用者には制限が残るため、通常成功と既知エラーを分けて公開した。
- レビューで確認したdangling elseの既存挙動は維持し、旧版で失敗するraw string、typedef二重ポインター、複雑なべき乗左辺、スライス端点省略を新しい構文として追加していない。未対応入力が引き続き失敗する制限は残る。旧変換器の異常終了は設計どおり再現しない。

独立レビュー担当は包装・ブラウザテストを独自には再実行していない。表のテスト結果は実装担当が実行して確認する。任意のC++全構文への対応を追加する移植ではなく、既存Albatの言語境界を維持する。

## PR #3の追加レビュー対応

`else if`の後続`else`が切り離される問題と、`Box(3);`を`Box 3;`へ書き換える問題を修正した。前者はelse-ifを連続した条件分岐として出力し、後者は括弧内が名前付き宣言の形を満たす場合だけまとめた宣言を展開する。Albatの文法変更ではなく、旧版で成功する入力の互換性修正である。

`review_else_if_chain`と`review_temporary_construction`で旧版との比較を追加した。既存のまとめた宣言も回帰テストで維持を確認する。文字列の借用競合という指摘は、参照の最終使用が変更より前に終わるため再現せず、全ターゲット・全機能のビルド確認で判定した。

## 追加レビュー後の検証

enum解析の修正は`review_enum_members_are_not_statements`で修正前の失敗から成功への変化を確認した。追加した通常/匿名enum、enum class、明示的な構築式の3ケースは旧C++版との比較で3/3成功。ヘッダーを明示的mainの外へ配置する回避方法も実ヘッダーで確認した。

新たなレビューのうち既存のヘッダー制限は[Issue #4](https://github.com/hanjyou0811/Albat/issues/4)、C++の宣言として扱われる`Box(x);`は変換器外でも再現するため不具合対象外とした。

## if constexpr / switchレビュー対応後

2件とも修正前の回帰テストが解析エラーで失敗することを確認し、修正後は成功。追加の旧版比較2/2も成功。Rust側では不要なテンプレート分岐、else-if連鎖、コメント、case/defaultのブロック、連続ラベル、ブロック内Albat構文を検証する。旧版自体が壊れる組み合わせは互換性記録で区別した。


## 初期化・条件入力・テンプレート引数レビュー対応後

レビューの3例は修正前に失敗することを確認。修正後は旧C++版との比較3/3が成功。関数本体の判別ではconst&等の修飾を維持し、マクロ引数ではテンプレートのカンマと通常の比較・シフトを区別する。条件式から取り出した宣言にも通常の変換を適用する。Albatの構文・意味を追加変更する修正ではない。
